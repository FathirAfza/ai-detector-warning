# AI Detector False-Positive Risk Check

A skill for reviewing a piece of writing the user says they wrote themselves, and identifying which parts of it carry the stylistic fingerprints that make AI-detection tools flag genuinely human text as AI-generated — then suggesting concrete edits that keep the writer's meaning and voice while reducing that risk.

## Scope and a hard boundary

This skill exists to help with a real, well-documented problem: AI detectors have significant false-positive rates, especially against writers who write in a formal, structured, or non-native-English style — which describes a lot of academic writing, especially by ESL/EFL students.

This skill is **only** for text the user represents as their own original writing. Before doing a full analysis, form a view of whether that's plausible from context (e.g. the user is asking about a draft they're clearly working on, pasted from their own document, references their own competition/assignment). If the user instead says or implies the text was generated by an AI tool and they want it to pass as their own human work, do not use this skill for that — decline that specific ask the way you normally would, while still being willing to help with the legitimate parts of the request (e.g. writing their own draft from scratch in their own voice, discussed with them).

This skill also never invents a false sense of certainty. It produces a **heuristic risk estimate based on known stylistic patterns**, not the output of an actual trained AI-detection classifier — this skill has no access to GPTZero/Turnitin/etc.'s actual models. Always say so plainly in the output; never present the percentage as if it were a real detector's score.

## Process

1. **Confirm the text.** Get the full draft from the user (pasted text or an uploaded file). If it's long (multi-page KTI, full essay), work through it section by section rather than skimming.

2. **Scan for marker patterns**, in both Indonesian and English as relevant — see `references/markers.md` for the full catalogued list (contrastive "bukan X tapi Y" / "not just X but Y" constructions, tricolon/rule-of-three overuse, overly tidy closing/summary sentences per paragraph, stock transition words opening most paragraphs, hedging phrases like "penting untuk dicatat bahwa" / "it's important to note that", AI-associated vocabulary like "leverage", "landscape", "delve", "tapestry" or their Indonesian equivalents, and unnaturally uniform paragraph/sentence structure).

3. **Check structural regularity ("burstiness").** Human writing has uneven rhythm — short blunt sentences next to long winding ones, paragraphs of different lengths, occasional fragments or asides. Note where the draft is instead suspiciously uniform (every paragraph ~3 sentences, every sentence ~20 words, every section following an identical template).

3b. **Check heading–content fit.** If the draft has headings or section titles (bab, subbab, poster sections), check whether each section's content actually matches and develops its heading, rather than generic filler, drift into another section's topic, or repetition of other sections. See pattern 11 in `references/markers.md`.

4. **Locate and quote the highest-risk spots.** For each flagged passage, quote the actual sentence(s) from the user's draft (this is fine — it's their own text) and name the specific pattern that makes it read as AI-typical.

5. **Give a risk estimate.** Roll the findings into an overall qualitative band — Rendah / Sedang / Tinggi (Low/Medium/High) — with an approximate percentage range attached only as a rough illustration of that band, e.g.:
   - **Rendah (~0–25%)**: markers rare, sentence rhythm varied, structure irregular across paragraphs.
   - **Sedang (~25–50%)**: some recurring markers or moderately uniform structure, but real stylistic variation exists elsewhere.
   - **Tinggi (~50–75%+)**: dense markers, low sentence-length variance, near-identical paragraph templates, frequent AI-associated vocabulary.
   Make explicit that this band is this skill's own heuristic reading, not a calibrated probability, and that actual detector tools may score it differently (and can themselves be wrong in either direction).

6. **Give revision guidance per flagged spot**, not just a list of problems. For each one, suggest how to break the pattern — e.g. replace a tidy tricolon with an uneven list, cut a "bukan hanya X, tapi juga Y" into two shorter plain sentences, drop a hedge phrase entirely, vary a run of same-length sentences by combining or splitting some. Keep the meaning intact and prefer edits that sound like something the writer would actually say — if the user has a distinctive voice or has shared how they usually write, match that instead of defaulting to generic "natural-sounding" prose.

7. **Optional standing checklist.** If the user wants something reusable for future drafts (rather than just this one), close with a short checklist version of the pattern categories they personally tend to hit, so they can self-check before submitting next time.

## Output format

Structure the response as:
1. **Skor risiko** — the qualitative band + illustrative percentage range, one or two sentences of reasoning, and the heuristic-not-a-real-detector disclaimer.
2. **Titik paling berisiko** — the flagged spots, each with the quoted original text, the pattern name, and why it reads as AI-typical.
3. **Saran revisi** — concrete rewrite suggestions per flagged spot (or per cluster of similar spots if there are many).

Keep it concise and skip padding — a short, direct writeup that gets to the specific spots fast is more useful here than a long preamble, matching the pattern this skill is itself trying to help the user avoid.
