# AI Detector False-Positive Risk Check

A skill for reviewing a piece of writing the user says they wrote themselves, and identifying which parts of it carry the stylistic fingerprints that make AI-detection tools flag genuinely human text as AI-generated — then suggesting concrete edits that keep the writer's meaning and voice while reducing that risk.

## Scope and a hard boundary

This skill exists to help with a real, well-documented problem: AI detectors have significant false-positive rates, especially against writers who write in a formal, structured, or non-native-English style — which describes a lot of academic writing, especially by ESL/EFL students.

This skill is **only** for text the user represents as their own original writing. Before doing a full analysis, form a view of whether that's plausible from context (e.g. the user is asking about a draft they're clearly working on, pasted from their own document, references their own competition/assignment). If the user instead says or implies the text was generated by an AI tool and they want it to pass as their own human work, do not use this skill for that — decline that specific ask the way you normally would, while still being willing to help with the legitimate parts of the request (e.g. writing their own draft from scratch in their own voice, discussed with them).

This skill also never invents a false sense of certainty. It produces a **heuristic risk estimate based on known stylistic patterns**, not the output of an actual trained AI-detection classifier — this skill has no access to GPTZero/Turnitin/etc.'s actual models. Always say so plainly in the output; never present the percentage as if it were a real detector's score.

## Process

1. **Confirm the text.** Get the full draft from the user (pasted text or an uploaded file). If it's long (multi-page KTI, full essay), work through it section by section rather than skimming.

2. **Scan for marker patterns**, in both Indonesian and English as relevant — see `references/markers.md` for the full catalogued list (contrastive "bukan X tapi Y" / "not just X but Y" constructions, tricolon/rule-of-three overuse, overly tidy closing/summary sentences per paragraph, stock transition words opening most paragraphs, hedging phrases like "penting untuk dicatat bahwa" / "it's important to note that", AI-associated vocabulary like "leverage", "landscape", "delve", "tapestry" or their Indonesian equivalents, and unnaturally uniform paragraph/sentence structure). Steps 4 and 5 below cover the context, slop, and repetition patterns (11–14) in more depth.

3. **Check structural regularity ("burstiness").** Human writing has uneven rhythm — short blunt sentences next to long winding ones, paragraphs of different lengths, occasional fragments or asides. Note where the draft is instead suspiciously uniform (every paragraph ~3 sentences, every sentence ~20 words, every section following an identical template).

4. **Check context coherence and heading fit (always do this step).** AI-generated text often reads smoothly sentence by sentence while the context doesn't actually connect. Check two levels:
   - **Between sentences** (pattern 14 in `references/markers.md`): for each pair of consecutive sentences, ask why the second follows the first. Flag jumps with no link, claims never tied to the actual subject, vague references ("hal ini", "perjalanan tersebut") to things never introduced, and conclusions the paragraph doesn't support.
   - **Section vs. heading** (pattern 11): for every heading, bab, subbab, or poster section, check whether its content answers and develops that heading, rather than generic filler, drift into another section's topic, or repetition of other sections. If the draft has no headings, check it against its title or the topic the user named.
   Report the result for every heading, including the ones that pass, so the user can see the whole document was checked.

5. **Check slop and repetition.**
   - **Slop** (pattern 12): flag generic sentences that carry no checkable information and would still be true about a different project ("di era modern ini", "menghadapi berbagai tantangan", "menuju masa depan yang lebih baik"), and inflated claims with no support.
   - **Repetition** (pattern 13): list content words appearing 3+ times in one paragraph and phrases of 2+ words appearing 2+ times, with counts. Don't flag consistent technical terms, proper names, or keywords the heading requires.

6. **Locate and quote the highest-risk spots.** For each flagged passage, quote the actual sentence(s) from the user's draft (this is fine — it's their own text) and name the specific pattern that makes it read as AI-typical.

7. **Give a risk estimate.** Roll the findings into an overall qualitative band — Rendah / Sedang / Tinggi (Low/Medium/High) — with an approximate percentage range attached only as a rough illustration of that band, e.g.:
   - **Rendah (~0–25%)**: markers rare, sentence rhythm varied, structure irregular across paragraphs.
   - **Sedang (~25–50%)**: some recurring markers or moderately uniform structure, but real stylistic variation exists elsewhere.
   - **Tinggi (~50–75%+)**: dense markers, low sentence-length variance, near-identical paragraph templates, frequent AI-associated vocabulary, generic filler, and context that doesn't connect to its heading or between sentences.
   Make explicit that this band is this skill's own heuristic reading, not a calibrated probability, and that actual detector tools may score it differently (and can themselves be wrong in either direction).

8. **Give revision guidance per flagged spot**, not just a list of problems. For each one, suggest how to break the pattern — e.g. replace a tidy tricolon with an uneven list, cut a "bukan hanya X, tapi juga Y" into two shorter plain sentences, drop a hedge phrase entirely, vary a run of same-length sentences by combining or splitting some, add the missing link sentence where context jumps, move off-topic sentences to the section they belong in, replace a generic filler sentence with one concrete detail from the writer's own work, cut repeated phrases after their first use. Keep the meaning intact and prefer edits that sound like something the writer would actually say — if the user has a distinctive voice or has shared how they usually write, match that instead of defaulting to generic "natural-sounding" prose.

9. **Optional standing checklist.** If the user wants something reusable for future drafts (rather than just this one), close with a short checklist version of the pattern categories they personally tend to hit, so they can self-check before submitting next time.

## Output format

Structure the response as:
1. **Skor risiko** — the qualitative band + illustrative percentage range, one or two sentences of reasoning, and the heuristic-not-a-real-detector disclaimer.
2. **Cek konteks dan heading** — one line per heading or section (or for the whole text if it has none): **Nyambung** / **Sebagian** / **Tidak nyambung**, with a short reason. Then list the context gaps between sentences found in step 4, and the repeated words/phrases with counts from step 5. Write "tidak ada" for a part with no findings instead of dropping it.
3. **Titik paling berisiko** — the flagged spots, each with the quoted original text, the pattern name, and why it reads as AI-typical.
4. **Saran revisi** — concrete rewrite suggestions per flagged spot (or per cluster of similar spots if there are many). When the fix needs information only the writer has (a design detail, a measurement, the real reason for a choice), leave a clear placeholder like `[sebutkan bagian desainnya]` instead of inventing it.

Keep it concise and skip padding — a short, direct writeup that gets to the specific spots fast is more useful here than a long preamble, matching the pattern this skill is itself trying to help the user avoid.
